## Design Context

### Users
A single user (the app's author), an astrophotography hobbyist shooting with a Seestar
S50 from a fixed home site. Used daily/nightly, often on a phone or laptop right before
heading outside, to decide "is tonight worth it" and "what should I point at." Not a
planning tool used ahead of time -- checked close to the moment of use.

### Brand Personality
NuitClaire. Quiet, precise, glanceable -- an instrument panel, not a marketing page.
Three words: functional, calm, trustworthy. No hype, no decoration for its own sake --
every visual element should help a single-person go/no-go decision faster.

### Aesthetic Direction
Minimal card-based layout (established already: `.card` blocks with translucent
rgba(127,127,127,x) surfaces that adapt to Streamlit's light/dark theme). French UI
throughout, 24h time format only. Theme: whatever Streamlit's user-level light/dark
setting is (not fixed) -- the existing rgba-on-gray technique already handles both;
new components should keep using it rather than hard-coded light- or dark-only colors.
No custom fonts/branding layer -- this rides on Streamlit's default typography by
design (proof-of-concept scope, cf. docs/plans/2026-09-15-noctar-features-design.md).

### Design Principles
1. Numbers and status (the score, the times, the altitude) are what the eye should
   catch first -- labels are secondary and should recede (mirrors the existing
   `.card h4` treatment: small, uppercase, muted).
2. Nothing is decorative-only. Every color, badge, or highlight encodes real data
   (cloud band, best-window highlight, now-marker) -- no ambient gradients or icons
   added purely for visual interest.
3. Consistency over novelty: new components (twilight bar, target cards) should read
   as the same system as the existing `.card` blocks, not a competing style.
